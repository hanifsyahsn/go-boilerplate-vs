# 0013 — Lint: staticcheck + golangci-lint (`make lint`)

Status: built (2026-11-10)

## Decision
1. **`make lint`** runs **staticcheck** (`staticcheck.conf`) and **golangci-lint v2** (`.golangci.yml`). Both run
   even when the first fails; the target fails at the end if either did. It stays green, like `make sec`.
2. Versions are pinned in the Makefile (`STATICCHECK_VERSION`, `GOLANGCI_LINT_VERSION`), installed with
   `make lint_install`. golangci-lint must be built with a Go at least as new as go.mod's.
3. staticcheck: **every check except ST1000** (a package comment on every package — noise for vertical slices).
   golangci-lint runs the same staticcheck set, so an editor using golangci-lint alone sees the same findings.
4. golangci-lint: the `standard` set (errcheck, govet, ineffassign, staticcheck, unused) plus bodyclose,
   copyloopvar, errorlint, misspell, nilerr, noctx, nolintlint, rowserrcheck, sloglint (`context: scope` = the
   `*Context` variant whenever a ctx is in scope), sqlclosecheck, testifylint, unconvert, usestdlibvars.
   Formatters: gofmt + goimports (`make fmt` applies them). Security linters stay in `make sec` (gosec).
5. Generated code (sqlc, mockgen) is excluded. Two scoped exclusions, each with its reason in the config:
   noctx in tests / `testhelper`, testifylint's `float-compare` (JSON numbers decode to float64; tests compare
   exact integers).
6. A finding is fixed, or a false positive silenced **on its own line with the reason**:
   `//nolint:<linter> // why` (golangci-lint; `nolintlint` rejects a bare one), `//lint:ignore <check> why` on
   the line before (standalone staticcheck). Never a blanket exclude.
7. **`*.go text eol=lf`** in `.gitattributes`: with `core.autocrlf=true` (Windows) every Go file would otherwise
   be checked out with CRLF and fail gofmt.
8. Unlike `make sec`, lint has **no local-only guard**: no secrets, no outbound calls, cheap enough for CI.

## Why
`go vet` alone misses dead code, unchecked errors, `%v` instead of `%w`, slog calls that drop the request id
(non-`*Context` variant), testify misuse and formatting drift. One config here means every derived service
lints the same way.

## Adopting it in a derivative
Copy `.golangci.yml`, `staticcheck.conf`, the Makefile `lint` / `fmt` / `lint_install` block and the
`.gitattributes` line; renormalise the Go files to LF; run `make lint` and fix the findings (expect initialisms
such as `Id` → `ID`, `%v` → `%w`, unchecked `Close`, testify `require.True(errors.As(...))` → `require.ErrorAs`).
A fix that changes behaviour (e.g. an error now wrapped with `%w`) gets a behaviour test.
