# 0009 — CORS

Status: built (2026-11-11).

## Decision
A CORS middleware with an origin allowlist from env (the same config as 0004); credentials allowed only for
listed origins, never `*` with credentials.

## Why
Several derivatives each have their own; the boilerplate has none.

## As built
- `ALLOWED_ORIGINS` (optional, comma separated): each entry `scheme://host[:port]` (http / https, no path other
  than `/`, query, fragment or user info; `*` refused), checked in `Config.Validate`, stored normalised
  (lowercase, no trailing `/`). Empty turns CORS and the origin guard (0004) off, with a startup warning.
- `middleware.CORS(allowedOrigins)` on the engine right after recovery, so a preflight (an `OPTIONS` no route
  declares) gets CORS's answer instead of the 405. A listed origin is echoed with
  `Access-Control-Allow-Credentials: true` and `Access-Control-Expose-Headers: Location, Retry-After,
  X-Request-ID`; its preflight is a 204 with methods `GET, POST, PATCH, DELETE`, headers `Accept, Authorization,
  Content-Type, X-Request-ID`, max age 600. An unlisted origin gets no CORS header; its preflight is a JSON:API
  403 `forbidden` ("This origin isn't allowed.", `source.header` `Origin`). Every response gets `Vary: Origin`,
  added next to `Vary: Accept` (`JSONAPIMediaType` now adds instead of setting).
